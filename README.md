## 1. `min-char-rnn.py` — посимвольная RNN на NumPy

Модель читает текст **посимвольно** и учится угадывать **следующий символ** по предыдущим. Это языковая модель — в итоге она умеет «писать текст».

### Данные и словарь (строки кода наверху файла)

```python
chars = list(set(data))                 # все уникальные символы текста -> словарь (V)
char_to_ix = {ch: i for i, ch in enumerate(chars)}  # символ -> индекс
ix_to_char = {i: ch for i, ch in enumerate(chars)}  # индекс -> символ (для вывода текста)
```

Гиперпараметры: `hidden_size = 100` (размер скрытого состояния), `seq_length = 16` (на сколько шагов раскатываем RNN за одну итерацию), `learning_rate = 0.1`, `MAX_DATA = 1 000 000` (лимит символов обучения).

### Веса модели (все общие для всех временных шагов!)

| Параметр | Размер | Смысл |
|---|---|---|
| `Wxh` | (H, V) | вход x → скрытое состояние h |
| `Whh` | (H, H) | скрытое состояние h(t-1) → h(t) — «память» |
| `Why` | (V, H) | скрытое h → выход y (логиты для софтмакса) |
| `bh`, `by` | векторы | смещения |

Вход на каждом шаге — **one-hot вектор** символа (размер V, единица на месте индекса символа).

### `lossFun(inputs, targets, hprev)` — сердце файла

Считает **одновременно прямой и обратный проход** по последовательности.

**Прямой проход** — по шагам `t = 0..seq_length-1`:

```
h[t] = tanh(Wxh·x[t] + Whh·h[t-1] + bh)      # обновление скрытого состояния
y[t] = Why·h[t] + by                         # сырые оценки (логиты)
p[t] = softmax(y[t])                         # вероятность следующего символа
loss += -log(p[t][targets[t]])               # кросс-энтропия, т.к. правильный ответ — один символ
```

Всё, что нужно для backward (x, h, y, p на каждом шаге) кешируется в словарях `xs, hs, ys, ps`.

**Обратный проход (BPTT — backprop через время)** — идём по шагам **наоборот**, от конца к началу:

```python
dy = np.copy(ps[t]); dy[targets[t]] -= 1   # градиент софтмакса + кросс-энтропии: p - 1(верный)
dWhy += dy · hs[t].T;  dby += dy           # градиенты последнего слоя
dh = Why.T·dy + dhnext                     # градиент к h: свой + пришедший от следующего шага
dhraw = (1 - h[t]²) · dh                   # производная tanh
dWxh += dhraw·x[t].T;  dWhh += dhraw·h[t-1].T;  dbh += dhraw
dhnext = Whh.T·dhraw                       # уйдёт на предыдущий шаг
```

То, что `dhnext` передаётся на предыдущий шаг — и есть «прокидывание градиента через время». Вес `Whh` участвует на каждом шаге, поэтому его градиент — **сумма** вкладов всех шагов.

В конце — **клиппинг градиентов** в диапазон [-5, 5] (лечит «взрыв градиента» — главную болезнь ванильной RNN).

Возвращает loss, все градиенты и последнее скрытое состояние `hs[-1]` (оно пойдёт стартовым в следующую итерацию — так модель «помнит» текст между окнами по 16 символов).

### `sample(h, seed_ix, n)` — генерация текста

Прогон модели **только вперёд**: даём стартовый символ, на каждом шаге берём не argmax, а **случайную выборку** из распределения softmax (`np.random.choice`), выбранный символ становится входом следующего шага. Так модель каждые 1000 итераций печатает кусочек сгенерированного текста — по нему видно, как учится.

### `gradCheck(...)` — проверка градиентов численно

Классическая проверка Backprop: чуть шевелим один вес (`±delta`), сравниваем аналитический градиент с численным `(loss(+δ) - loss(-δ)) / 2δ`. Относительная ошибка должна быть крошечной (в нашем прогоне ~1e-9). Включается флагом `--grad-check`, обучение при этом не запускается.

### Тренировочный цикл (`train(...)`)

1. Окно из `seq_length` символов: `inputs = data[p:p+16]`, `targets = data[p+1:p+17]` — цель просто «сдвиг на 1» (каждый вход сопровождается следующим символом).
2. `lossFun(...)` → loss + градиенты + обновлённое `hprev`.
3. **Adagrad** — адаптивный шаг обучения: каждый параметр делится на корень суммы квадратов своих прошлых градиентов (`mem += g²`, `param -= lr·g/√mem`).
4. `smooth_loss` — сглаженный loss (умножение на 0.999 + 0.001 нового), чтобы видеть тенденцию.
5. При затухании `p+seq_length+1 >= len(data)` — сброс `p` в 0 и `hprev` в нули.

## 2. `min-char-lstm.py` — то же самое, но LSTM (вручную)

Задача та же — предсказание следующего символа, но вместо простого `tanh(Wxh·x + Whh·h)` в ячейке — **полноценная LSTM-ячейка** с явными вратами. Код — по статье Eli Bendersky (eli.thegreenplace.net), структура — по Karpathy's min-char-rnn.

### Веса

| Параметр | Размер | Смысл |
|---|---|---|
| `Wf, bf` | (H, H+V) | **forget gate** — «что стереть из памяти c» |
| `Wi, bi` | (H, H+V) | **input gate** — «сколько нового записать в c» |
| `Wcc, bcc` | (H, H+V) | кандидат на новое содержимое памяти `c̃` (tanh) |
| `Wo, bo` | (H, H+V) | **output gate** — «сколько из c показать наружу как h» |
| `Wy, by` | (V, H) | выход-слой, как у RNN |

Трюк: вход ворот — **конкатенация** `[x; h]` (столбец x сверху вектора h), размер `HV = V + H`. Собирает её `np.vstack((xs[t], hs[t-1]))` в `xhs[t]`. Поэтому во всех матрицах второй размер — `HV`, а не `V`.

### Уравнения ячейки (прямой проход, шаг t)

```
f = σ(Wf·[x;h] + bf)          # новый: 0 — стереть, 1 — оставить (ворота забывания)
i = σ(Wi·[x;h] + bi)          # сколько нового пропустить
c̃ = tanh(Wcc·[x;h] + bcc)     # новый-кандидат в память
o = σ(Wo·[x;h] + bo)          # сколько памяти выпустить наружу

c[t] = f ⊙ c[t-1] + i ⊙ c̃     # ОБНОВЛЕННАЯ ДОЛГОВРЕМЕННАЯ ПАМЯТЬ (cell state)
h[t] = tanh(c[t]) ⊙ o         # кратковременное состояние (то, что видит выход)
y[t] = Wy·h[t] + by;  p[t] = softmax(y[t])
```

Зачем врата: у ванильной RNN вся память — `h`, и градиент через `tanh` и `Whh` затухает/взрывается на длинных цепочках. У LSTM память `c` проходит сквозь шаги почти напрямую (`c[t] = f⊙c[t-1] + ...`) — умножение на `f`, близкий к 1, **сохраняет** градиент. Поэтому LSTM ловит длинные зависимости (например, обороты через 10–20 символов), недоступные RNN.

### `lossFun(...)` — как у RNN, но backward заметно толще

Обратный ход:

```python
dy = p - 1(верный)                       # как в RNN
dh = Wy.T·dy + dhnext                     # градиент «к h» с этого шага
dctanh = o ⊙ dh                           # через выходные ворота
dc    = dctanh · (1 - tanh(c)²) + dcnext  # производная tanh(c); + ветка от буд. шага (c ветвится!)
dhogs  = dh · tanh(c)                     # градиент к выходу ворот o
dho    = dhogs · o(1-o)                   # назад через sigmoid
dWo += dho·xhs.T;  dbo += dho; ...

# входные ворота
dhi = c̃ · dc · i(1-i);  dWi += dhi·xhs.T; ...
# кандидат
dhcc = i · dc · (1 - c̃²);  dWcc += dhcc·xhs.T; ...
# забывающие ворота
dhf = c[t-1] · dc · f(1-f);  dWf += dhf·xhs.T; ...

dxh = Σ вкладов ворот (через Wo.T/Wf.T/Wi.T/Wcc.T)
dhnext = dxh[V:]      # верхняя половина dxh — про x, нижняя (dxh[V:]) — градиент к h
dcnext = f ⊙ dc       # градиент к c прошлого шага
```

Ключевое отличие от RNN: сюда идут **два** потока градиента, `dhnext` и `dcnext`, вместо одного `dhnext`. Клиппинг [-5, 5] тоже есть.

### Отличия от RNN-версии

* состояние стало двойным: `sample(h, c, seed_ix, n)` держит и `h`, и `c`;
* тренировочный цикл хранит `Adagrad`-память для 10 параметров вместо 5;
* сброс: `hprev = cprev = 0` при начале нового прохода по тексту;
* всё остальное — 1-в-1 как в RNN (окна 16 симв., цели со сдвигом 1, каждые 1000 итераций печать сгенерированного текста).

## 3. `lstm_torch.py` — прогноз временного ряда на PyTorch

Совсем другая задача: **регрессия по временно́му ряду** — по последним 4 значениям предсказать следующее. Здесь чётко видно отличие от ручных скриптов: backprop/Adagrad уже не нужны руками — PyTorch делает за нас (`loss.backward()`, Adam).

### `sliding_windows(data, seq_length)` — нарезка ряда на окна

Скользящее окно: x — окно из `seq_length=4` прошлых значений (форма (N, 4, 1)); y — значение, идущее **сразу за окном**. Получаем `x[i..i+3] → y[i+4]`.

### `load_data(dataset_name, dataset_label)` — подготовка данных

1. Читает CSV (`pd.read_csv`), берёт колонку 1 (только значения, без дат), рисует исходный ряд.
2. `MinMaxScaler` — все значения в диапазон [0, 1] (нейросети так учиться намного легче).
3. Дальше — `sliding_windows` с окном 4.
4. **Деление**: первые 67 % точек — train, остальные 33 % — test. Входные данные оборачиваются в `torch.Tensor` (в исходном ноутбуке для этого использовался устаревший `Variable`, который больше не нужен).
5. Возвращает `sc` (скейлер, чтобы инвертировать результат в обычные числа), метки train/test и 4 тензора.

### `class LSTM(nn.Module)` — модель

* `__init__`: `nn.LSTM(input_size=1, hidden_size=2, num_layers=1, batch_first=True)` (hidden_size всего 2 — модель миниатюрная, задача простая) + `nn.Linear(hidden_size, num_classes)` (num_classes=1) — превращает h в предсказание значения.
* `forward(x)`:
  1. Инициализация нулевых состояний `h_0`, `c_0` (размера (num_layers, batch, hidden)).
  2. Прогон через `self.lstm` → `ula` (все h по шагам) и `(h_out, _)` (последние h, c).
  3. `h_out.view(-1, hidden_size)` — вытягивание последнего h в матрицу (batch, hidden);
  4. `self.fc(h_out)` — линейный слой даёт **предсказ одного следующего значения** на каждое окно.

Обратите внимание: здесь используется **выход только в конце последовательности** (последнее скрытое состояние). Вход — число, а не one-hot, и выход — число, а не вероятности символов.

### `train_and_test_model(...)` — цикл обучения

```python
criterion = nn.MSELoss()               # регрессия → средне-квадратичная ошибка (не кросс-энтропия)
optimizer = torch.optim.Adam(lr=0.01)  # не Adagrad, как выше, а Adam
for epoch in range(2000):
    outputs = lstm(trainX)             # предсказ для ВСЕХ train-окон сразу (батч) — state между окнами не передаётся
    optimizer.zero_grad()              # обнулить градиенты прошлой итерации
    loss = criterion(outputs, trainY)  # MSE
    loss.backward()                    # обратный проход (PyTorch сам, включая BPTT по LSTM)
    optimizer.step()                   # шаг Adam
```

Каждые 100 итераций печатаем loss — он должен падать.

### Финальная проверка и график

1. `lstm.eval()` — переключение модели в режим инференса (отключает dropout и т.п.; для этой сети формально).
2. Прогон на **всех** данных `lstm(dataX)`.
3. `sc.inverse_transform(...)` — возвращаем из [0, 1] в реальные значения пассажиров/продаж.
4. Рисуем оба: реальный ряд и предсказанный; **красная вертикальная пунктирная линия** — граница train/test: слева от неё — train-часть (модель видела эти точки при обучении), справа — настоящая проверка, насколько разумно предсказ ведёт себя на незнакомых данных.
5. Точка входа — `argparse`: по умолчанию запускается ряд пассажиров авиакомпаний, `--dataset data/shampoo.csv` переключает на шампуни.

## Лабораторная часть: что доделано под методичку

Методичка (п. 3.2) требует: замерить время обучения, сохранять значения критерия качества по ходу обучения, сохранить графики качества в файл, прогнать RNN и LSTM на `input.txt` и `cnus-clean.txt`, прогнать `lstm_torch.py` на двух рядах, сравнить графики и оформить PDF. Всё это добавлено.

### Что добавлено в скрипты

Во все три скрипта добавлены аргументы командной строки (файл данных, число итераций/эпох, каталог результатов, тег), чтобы один и тот же код можно было прогонять на разных наборах без правок. В `min-char-rnn.py` и `min-char-lstm.py`:

* обучение обёрнуто в функцию `train(...)`, время обучения замеряется `time.perf_counter()`;
* `loss` (и сглаженный, и на одном окне) пишется в CSV на каждом логируемом шаге;
* строятся графики «качество от номера этапа» (PNG + PDF);
* сгенерированные тексты сохраняются в `*_samples.txt` и в персональный PDF-отчёт прогона;
* есть флаг `--grad-check` — численная проверка градиентов (посчитанные вручную производные сверяются с `(L(+δ)−L(−δ))/2δ`; относительная ошибка ~1e-9, т.е. обратное распространение реализовано верно).

В `lstm_torch.py` добавлены сохранение MSE по эпохам (CSV/график), график прогноза (PNG/PDF), метрики RMSE на train/test в исходных единицах и замер времени.

Как это читать:

* `smooth_loss` — это **сумма** кросс-энтропий по 16 символам окна, поэтому делить на 16: у RNN ~2.0 на символ, у LSTM ~1.5–1.7. Стартовое значение (случайное угадывание) — `ln(V)·16` ≈ 64–67.
* LSTM на том же объёме данных медленнее RNN примерно в 4 раза (десять матричных умножений на шаг вместо трёх), но стабильно даёт меньший loss — на `input.txt` 26.64 против 32.37, на `cnus-clean.txt` 24.48 против 32.04.
* Численная проверка градиентов (`--grad-check`) для обеих ручных реализаций даёт относительную ошибку порядка 1e-9 — формулы обратного распространения совпадают с численной производной.
* У torch-модели ошибка на test-части заметно выше train: сеть крошечная (`hidden_size = 2`), ряд airline — 139 окон, shampoo — всего 31 окно (11 в тесте), поэтому хвост прогноза уходит в сторону. Для `shampoo` это особенно видно: train RMSE 24.2 против test 246.2. Это честный результат для заданных методичкой гиперпараметров; увеличив `--hidden` и `--epochs`, ошибку можно уменьшить.

## Самые важные выводы (если лабу будут допытывать)

1. **RNN vs LSTM**: RNN умеет помнить только очень недалёкое (градиенты через время затухают/взрываются → поэтому в коде клиппинг). LSTM с воротами f/i/o хранит долговременную память `c` и сквозь неё прокидывает градиент — учится на зависимостях, недоступных RNN.
2. **BPTT**: все веса в RNN общие между шагами, поэтому прямой проход раскладывает последовательность по шагам, а обратный идёт по ней назад и суммирует вклады всех шагов времени в градиент каждого веса.
3. **Ручной backprop vs PyTorch**: в NumPy-скриптах backprop выписан формулами — чтобы было видно, как он работает. В torch-скрипте `loss.backward()` делает то же самое автоматом: здесь на первом плане уже применение модели к прогнозированию.
4. **Разные задачи — разные входы/выходы**: символьная модель — one-hot вход (V) + softmax вероятность следующего символа + кросс-энтропия. Временный ряд — числовой вход (1) + число на выходе + MSE + MinMaxScale.
5. **Проверка градиентов** (`gradCheck`) — стандартный приём: аналитические градиенты сверяются с численными; крошечная относительная ошибка (rel_error ≈ 1e-7) означает, что backward написан правильно.
